# Android & Google Play Publishing

Global Messenger now has the Capacitor configuration and Android CI bootstrap needed to package the existing React/Vite app as an Android application.

## 1. Architecture

```text
React + Vite web app
        |
        | Capacitor
        v
Android application
        |
        | HTTPS / WSS
        v
Fastify + Socket.IO API
        |
        v
PostgreSQL / Prisma
```

The Android app uses the same messaging, authentication and calling backend. This keeps web and Android behavior aligned.

## 2. What is already configured

The repository contains:

- `apps/web/capacitor.config.ts`
- Capacitor Android dependencies in `apps/web/package.json`
- Root Android helper commands in `package.json`
- `.github/workflows/android-build.yml`
- Android application ID: `com.globalmessenger.app`
- Android application name: `Global Messenger`
- Web output directory: `dist`
- HTTPS Android scheme
- CI permissions for Internet, camera, microphone and notifications

The Android directory is intentionally generated by Capacitor instead of committing a large generated Gradle project immediately. This makes the native project reproducible in local development and CI.

## 6. Production backend requirement

Do not point the Play Store build at `localhost` or a development machine.

Use production HTTPS/WSS endpoints, for example:

```text
https://api.example.com
wss://api.example.com
```

Configure the production API URL through the application's production configuration before creating the release build.

For WebRTC calls, configure production STUN/TURN infrastructure. A TURN server is important for users whose networks cannot establish a direct peer-to-peer connection.

## 7. Android permissions

Global Messenger requires permissions related to its core features:

- Internet — realtime messaging and media
- Camera — video calls
- Microphone — voice/video calls
- Notifications — message and incoming-call notifications

The permission request must explain the purpose to users. Do not request unrelated permissions.

## 8. Build a release App Bundle

After the Android project is generated:

```powershell
cd C:\Users\91938\Desktop\global-messanger\apps\web
npm run build
npx cap sync android
npx cap open android
```

In Android Studio:

1. Confirm the application ID is `com.globalmessenger.app`.
2. Confirm the app name is `Global Messenger`.
3. Set the production API endpoint.
4. Configure launcher icons and splash assets.
5. Set the version name, for example `1.0.0`.
6. Set a unique increasing version code, for example `1`.
7. Create or import the release signing key.
8. Build a **signed Android App Bundle (`.aab`)**.

Never commit the keystore, passwords or signing secrets to GitHub.

## 9. Google Play target API

As of **August 31, 2026**, new apps and app updates submitted to Google Play must target **Android 16 / API 36 or higher**. Google also states that an extension can be requested until November 1, 2026 in applicable cases. Verify the current Play Console requirement before every release. citeturn0search0

Therefore, this project should be built with Android SDK/API 36 or newer for the first public Play Store release.

## 10. GitHub Actions Android build

The repository contains:

```text
.github/workflows/android-build.yml
```

It:

1. Checks out the repository.
2. Installs Node.js.
3. Installs Java.
4. Installs npm dependencies.
5. Builds the React application.
6. Generates the Android project with Capacitor.
7. Synchronizes web assets.
8. Adds required Android permissions.
9. Builds a debug APK.
10. Uploads the APK as a GitHub Actions artifact.

This CI build is for repeatable testing. It is **not** the final Play Store signed release.

## 12. Testing tracks

Use the Play Console tracks in this order:

```text
Internal testing
      ↓
Closed testing
      ↓
Open testing (optional)
      ↓
Production
```

For a messaging application, keep the app in testing until two or more independent accounts can reliably exchange messages and complete calls on real Android devices.
