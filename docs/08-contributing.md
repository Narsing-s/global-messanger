# Contributing

Thank you for helping improve Global Messenger.

## Before coding

1. Open or create an issue describing the problem or feature.
2. Explain expected behavior.
3. Keep changes focused.
4. Avoid committing secrets, local `.env` files or generated credentials.

## Development

```bash
npm install
npm run dev
```

## Pull requests

Include:

- What changed
- Why it changed
- How it was tested
- Screenshots for UI changes
- Any database/API migration notes
- Any security/privacy implications

## Quality expectations

Realtime messaging and calls are sensitive paths. Test with two accounts and test both success and failure/permission-denied flows.

## Issues

Useful bug reports include browser/device, exact steps, expected behavior, actual behavior and relevant console/server errors. Never include passwords, tokens or private user data.
